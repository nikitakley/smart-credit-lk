# Симулятор внешних источников

Отдельный сервис, который заменяет внешние системы, к которым банк обращается при рассмотрении заявки:

| Источник | Эндпоинт | Что отдаёт |
|---|---|---|
| ЕГРЮЛ / ЕГРИП | `GET /egr/v1/extracts/{inn}` | статус (действует, ликвидирована…), дата регистрации, руководитель, учредители, ОКВЭД |
| НБКИ | `POST /nbki/v1/credit-reports` | кредиты и платежи по ним, просрочки за 24 месяца, рейтинг бюро, число запросов истории |
| ФНС «Прозрачный бизнес» | `GET /pb/v1/companies/{inn}` | массовый адрес и руководитель, недостоверные сведения, налоговая задолженность, отчётность |

Смысл интеграции сохранён: сетевой сервис, ключ доступа, собственные форматы ответов (snake_case, своя структура),
задержки и сбои. Реальные сервисы не вызываются, все данные синтетические.

Swagger: http://localhost:8001/docs → кнопка *Authorize* → ключ `local-mocks-key` (или значение `MOCKS_API_KEY`).

## Данные

`data/egr.json`, `data/nbki.json`, `data/pb.json` — записи по ИНН пяти демо-компаний. Они согласованы
с сидами банка (`data/seed/`): тест бэкенда `test_demo_checks_match_live_sources` проверяет, что проверки
демо-заявок совпадают с тем, что дают симулятор и правила банка. Формат файлов проверяется моделями
из `simulator/models.py` при запуске: ошибка в данных останавливает сервис сразу.

| ИНН | Компания | Что показывает |
|---|---|---|
| 1655482318 | ООО «Продмаркет» | действует; два кредита, платежи 720 000 ₽/мес — высокая нагрузка |
| 7810624578 | ООО «Вектор Софт» | действует с 2018 года; хорошая история, признаков риска нет |
| 504718329642 | ИП Сидоров П. А. | ЕГРИП; кредитная история 11 месяцев; отчётности у ИП нет |
| 6671034827 | ООО «Уралстройинвест» | **ликвидирована**; налоговая задолженность, недостоверный адрес |
| 5406247181 | ООО «СибТоргКомплект» | **массовый адрес** (54 компании) |
| любой другой | — | ЕГРЮЛ и «Прозрачный бизнес» — 404; НБКИ — отчёт «кредитной истории нет» |

Особенности НБКИ, как у настоящего бюро:
- запрос только с согласием субъекта (`consent.given = true`), согласие действует 183 дня → иначе `403`;
- тип субъекта должен соответствовать ИНН (10 цифр — юрлицо, 12 — ИП) → иначе `400`;
- отсутствие кредитной истории — это отчёт с `history_found: false`, а не ошибка.

## Сбои и задержки

У каждого источника своё поведение. По умолчанию — из переменных окружения, во время работы меняется через API:

```bash
KEY="X-Api-Key: local-mocks-key"
# НБКИ недоступен (503)
curl -X PUT localhost:8001/admin/sources/nbki -H "$KEY" -H "Content-Type: application/json" -d '{"mode": "error"}'
# «Прозрачный бизнес» зависает (ответ через MOCK_TIMEOUT_SECONDS, затем 504)
curl -X PUT localhost:8001/admin/sources/pb -H "$KEY" -H "Content-Type: application/json" -d '{"mode": "timeout"}'
# ЕГРЮЛ отвечает медленно и сбоит в 30% случаев
curl -X PUT localhost:8001/admin/sources/egr -H "$KEY" -H "Content-Type: application/json" \
     -d '{"latency_min_ms": 2000, "latency_max_ms": 4000, "failure_rate": 0.3}'
# Вернуть всё как было
curl -X POST localhost:8001/admin/reset -H "$KEY"
# Последние запросы банка к источникам (с X-Request-Id для поиска в логах бэкенда)
curl "localhost:8001/admin/requests?limit=20" -H "$KEY"
```

То же самое удобно делать из Swagger, раздел «Управление симулятором».

| Режим | Поведение |
|---|---|
| `normal` | ответ через случайную задержку `latency_min_ms…latency_max_ms`; с вероятностью `failure_rate` — 503 |
| `error` | сразу 503 — сервис недоступен |
| `timeout` | зависание на `MOCK_TIMEOUT_SECONDS`, затем 504 (бэкенд перестаёт ждать раньше) |

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MOCKS_API_KEY` | `local-mocks-key` | ключ доступа (заголовок `X-Api-Key`) |
| `MOCK_LATENCY_MIN_MS`, `MOCK_LATENCY_MAX_MS` | `300`, `1200` | задержка ответа по умолчанию, мс |
| `MOCK_FAILURE_RATE` | `0` | доля случайных ответов 503 |
| `MOCK_TIMEOUT_SECONDS` | `30` | длительность «зависания» в режиме `timeout` |
| `MOCK_DATA_DIR` | `mocks/data` | папка с данными |

## Запуск

В Docker поднимается вместе со всем проектом (`docker compose up --build -d` из корня). Отдельно, без Docker:

```bash
cd mocks
uv sync
uv run uvicorn simulator.main:app --port 8001 --reload
uv run pytest                                  # тесты симулятора
uv run python scripts/export_openapi.py        # → docs/api/mocks-openapi.json
```

## Структура

```
simulator/
├── main.py         # приложение, журнал запросов, /health
├── config.py       # настройки из переменных окружения
├── models.py       # форматы ответов источников (и проверка data/*.json)
├── store.py        # загрузка данных
├── faults.py       # задержки, сбои, режимы источников
├── journal.py      # журнал последних запросов
├── security.py     # ключ доступа
└── routes/         # egr, nbki, pb, admin
data/               # синтетические данные источников
```
